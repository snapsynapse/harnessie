# Offline AIDR export

`harnessie export-aidr` exports one existing open Harnessie contested-phase record into an explicitly named AIDR file. This command is unreleased source functionality and is not included in the published PyPI 1.3.1 package. Use a checkout containing this command and its installed Python dependencies on a POSIX system supporting `flock`, no-follow file access, and hard links, such as macOS or Linux. Export does not require Node, model credentials, or a running workflow.

## Invocation

Select the source run and phase, reserve an unused AIDR ID in the project's existing `decisions/` directory, and declare the human who will arbitrate. The source is `runs/RUN_ID/decisions/DR-PHASE.md`. The destination must be directly inside the project root's `decisions/` directory, with a filename of the form `AIDR-NNNN-short-slug.md`.

Replace: PROJECT_ROOT -> path to the existing Harnessie project.
Replace: RUN_ID -> existing run directory name.
Replace: PHASE -> phase name identifying the open source decision.
Replace: NNNN -> unused AIDR ID of at least four digits in the destination directory.
Replace: SHORT_SLUG -> lowercase filename slug for the decision.
Replace: HUMAN_HANDLE -> declared human arbiter handle.
Customize
```bash
python3 -m harness.cli --root "PROJECT_ROOT" export-aidr "RUN_ID" "PHASE" --output "decisions/AIDR-NNNN-SHORT_SLUG.md" --arbiter "HUMAN_HANDLE"
```
`--root` precedes the command. Both `--output` and `--arbiter` are required; the exporter does not allocate an ID or infer a human identity. A declared arbiter does not authenticate the caller, the original record's author, or any future editor.

## Output and exit codes

Success prints one JSON object on standard output with `status: "exported"`, the root-relative `output`, `source_sha256`, `evidence_sha256`, `output_sha256`, and `target_spec: "0.1.0"`. Exit 0 means the export completed. It does not mean the workflow passed, the decision was approved, or a human arbitrated it.

An export refusal prints one JSON object on standard output with `status: "refused"` and a machine-readable `code`, then exits 2. Argument syntax errors use the CLI's normal usage diagnostic on standard error and also exit 2. Export does not overwrite an existing destination. A repeat attempt against the same destination refuses; deterministic content is not an overwrite permission.

## Accepted source and preservation

The source must be an unambiguous open `DR-PHASE` record with valid identities, resolvable run evidence, and an empty Arbitration section. Any decided metadata or arbitration content refuses export, including content in a record still marked open. Missing evidence, malformed structures, unsafe paths, symlink paths, and destination ID or filename collisions also refuse.

The parser accepts a strict subset of canonical records generated by Harnessie's `assemble_record`: flat frontmatter; the Context, Question, Positions, Objections, Arbitration, and Evidence sections in their emitted order; and the single emitted reference to that run's hash-chained `events.jsonl`. Manually reformatted records and extra evidence references are unsupported. Unquoted headings (including indented, list-nested and setext headings), code fences, raw HTML/comments and Unicode line separators refuse because they can obscure record boundaries. Blockquoted heading and fence examples remain prose. These restrictions apply even when the original runtime accepted the text; export never silently rewrites it to pass. Source records are limited to 2 MiB and event evidence to 64 MiB. Run and phase names use letters, digits, underscores, and hyphens, begin with a letter or digit, and are limited to 128 characters. The destination slug uses lowercase letters and digits separated by single hyphens.

The export preserves recorded position prose and objections, keeping initial positions and objections separate. Unique participant-instance labels distinguish repeated roles; provenance retains the original role and source label. Reported model and provider values remain reported identities. An objection addressed to the decision remains addressed to the decision.

The destination stays open with empty Arbitration. The command does not resume the runner, initialize models, call providers, or modify the source record, event log, or workflow state. It performs structural validation against the pinned AIDR 0.1.0 export contract before publishing the new file. Reference-linter tests establish structural compatibility for the tested artifacts, not semantic adequacy or blanket AIDR conformance.

Keep the source tree and destination directory under operator control during export. An advisory directory lock coordinates cooperating exporters, and exclusive hard-link publication prevents overwriting the destination. These controls do not confine hostile concurrent filesystem writers. Source and evidence bytes are rechecked immediately before publication. No directories are created by the command.

## Evidence limits

SHA-256 values bind the source record and consumed run evidence at export time. They do not establish original-generation authorship, prove that participants saw identical inputs, authenticate model/provider identities, or demonstrate that reviewers read each evidence item. Copying a source independence statement does not validate that statement.

Harnessie creates initial positions in separate model contexts within one process, with read-only tool grants. Shared filesystem access and differing role prompts limit what that separation proves. The exporter cannot retroactively establish independent blind review, immutable original inputs, or independent external runtimes.

Existing objection parsing truncates each objection to 500 characters; objection events retain at most 200 characters of text. The assembled source record does not retain the original objection-round prose or round numbers. The export preserves the recorded text and discloses the upstream truncation limit. It cannot reconstruct omitted text from an older run or supply a complete response transcript. Position summaries also have an upstream 500-character limit.

Run evidence can contain sensitive project material. The output carries recorded decision content and source references; review it before sharing. The export is a local artifact operation and grants no publication authority. Human arbitration, imports back into Harnessie, live review panels, and runtime behavior changes are outside this command.
